# 0.3.3 首次課表載入與畢業門檻

## 目標

- 首次登入課表建立 Session、跳轉及查詢必須等待正確就緒條件，減少反覆手動整理。
- 畢業門檻以已完成、尚差數量及未知資料為主；縮減 Hero 佔用、避免以估算百分比冒充官方判定。
- 保留原有 Flutter 資料模型、API、手動更新與課表快取。

Android WebView 合成校務頁面整合測試通過；最終 debug APK 建置、簽署驗證與下載 HTTP 200 通過，已發布0.3.3。真實帳號首次登入仍須實際使用確認。

靜態分析無問題、完整146項 Flutter 測試通過；Node fixtures 覆蓋首次登入、延遲POST、部分DOM、舊文件、合法空課表與 UpdatePanel。

## 已確認調整

- 剛完成校方驗證的 Session 開啟課表時直接交換 GUID，不再先重跑儲存還原與身分驗證。
- 以 fixture 驗證首次登入後 academic entry 不重複呼叫身分 API。
- 移除 GUID 登入頁尚未完成時強制跳 MainFrame 的行為，等待校方真正的 redirect。
- 課表查詢改為文件範圍狀態：按鈕可用→單次查詢→POST／UpdatePanel 回應→兩次穩定觀察，再擷取表格。避免把查詢前空表當結果。
- 文件 signature／unload／generation 檢查淘汰舊頁面回呼；子框架未觸發 onLoadStop 仍可發現資料。

## 畢業門檻

- 摘要改為完成／未完成／未知項數，環形指標縮小至64px，避免大面積估算百分比造成誤解。
- 學分優先，接續時數、能力資格與學程；已知數量顯示剩餘數，最低為0，未知不假裝0。
- 全部／待處理／已完成篩選，未知仍列待處理。
- 計算說明收至底部可展開區，尊重減少動畫設定。
- 9項畢業門檻測試通過，含320px／2x字體深淺色。
