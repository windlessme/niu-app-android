# Android 功能對照與驗證記錄

本文件將「實作」、「離線／模擬器驗證」及「校方真實帳號驗證」分別記錄。
可編譯或 fixture 通過不代表校方端到端操作已成功。

| 功能 | Android 交付範圍 | 真實環境依賴 |
| --- | --- | --- |
| 登入 | 可見 SSO、身分確認、GUID 交換、憑證保存、清除 | 有效學生帳號、校方驗證碼 |
| 課表 | 查詢、週表、今日安排、快照、ICS 匯出 | 校務頁與實際學期 |
| M 園區 | 課程、公告討論、教材、作業、成績 | Moodle Token 與課程權限 |
| 作業 | 附件選取、上傳草稿、儲存與正式提交 | 開放提交的作業與使用者操作 |
| 點名 | QR 掃描、網頁登入、結果分類、出缺席 | 課堂 QR 與有效點名時段 |
| 圖書館 | 門禁 QR、借書條碼、背景隱藏 | 學校圖碼服務與門禁設備 |
| 校曆 | 月曆／事件、年度、搜尋、分類、來源、遠端更新與離線 | 公開 GitHub JSON／校方 PDF |
| 歷年成績 | 表格擷取、學期／歷年資訊、GPA | 校務成績頁 |
| 畢業門檻 | 多元、英文、體適能資訊 | 校務門檻頁 |
| 活動 | 列表、詳情、已報名與校方報名表單 | 活動開放狀態 |
| Android Widget | 桌面課表、點擊進入課表、清除 | Android Launcher |
| 快捷 | 點名／圖書館入口 | 冷啟動與登入導流 |
| 課程通知 | 本機提醒、重開機恢復、取消 | 通知權限與 OS 電源管理 |
| 設定 | 外觀、隱私、支援、致謝、登出 | 實際資料流與聯絡信箱 |

## 平台差異

Apple 動態島與 Live Activities 在 Android 使用桌面 Widget／本機課程提醒提供相近用途。
遠端即時更新的 Apple 後端不在版本庫內，Android 不會宣稱已連上不存在的 FCM 服務。
OCR 便利流程不能成為登入必要條件；校方驗證碼始終保留人工操作路徑。

## 發行驗證記錄

### 0.5.1 自動保存帳密

- 登入頁移除勾選，成功校方驗證後自動加密保存帳密並供下次填入。
- 舊Token無法還原未保存的密碼；需要當次輸入且成功驗證。
- 忘記／登出仍清除，後續再次帳密登入會重新保存。

### 0.5.0 註冊資訊

- 新增查詢註冊資訊與本人在學證明操作，使用校務原始欄位，不推斷付款完成或註冊資格。
- 證明下載需驗證PDF格式，未將學生PDF放到公開下載目錄；詳見 `registration-feature-0.5.0.md`。

### 0.4.3 記住帳密

- 校務登入頁提供明示選項，成功驗證身分後才保存同帳號的加密帳密。
- 重新授權只在校方登入頁填入，不自動提交、不處理人機驗證。
- 設定可忘記帳密、關閉選項與登出均清除，已有其他有效服務Token不因忘記密碼而刪除。

### 0.4.2 活動體驗

- 活動報名列表／我的報名／詳情沿用既有Theme統整，增加搜尋與狀態資訊層級。
- 閱覽返回不等同資料修改，不再每次回列表都啟動校方網頁。
- 實際報名／修改／取消仍由使用者操作校方表單，以校方回應為準。

### 0.4.1 登入保留

- 單一校務驗證失效不再全域登出；同帳號快取與 Moodle／活動獨立登入仍保留。
- 首頁和設定顯示需要重連校務或暫時離線的狀態，各服務由自己伺服器驗證憑證。
- 仍無法讓校方已撤銷的 Token 永久有效；舊版本已刪除的憑證需登入重新建立。

### 0.2.5 活動登入

- 修正 0.2.4 僅嘗試 GUID、失敗後停留登入頁的問題；以實際活動表單建立活動 Session，沿用校務登入當次帳密。
- 舊版本使用者沒有活動 Cookie 時，需要使用「重新連接活動登入」完成一次校務登入；不要求卸載或清除課表快取。
- 登入後維持原本「我的報名」或活動詳情目標。實際活動認證仍需校方帳號驗證，不自動提交任何活動報名。
- 登入表單欄位／防偽 Token 以校方公開 HTML 確認；只提交 `Account/Login`，以受保護的 ApplyMe 回應判定成功，公開 Act 列表不能當成登入成功。

### 0.2.4 快取與登入整合

- 課表已有同帳號快取時直接顯示，手動更新才重新查詢校務頁；保持上次更新時間與離線標記。
- 深色模式重新設定背景／卡片／文字層級、Cupertino 配色、彈窗與分頁；設定切換立即同步並保存。
- 校方登入送出時暫存帳密建立 Moodle 登入，成功後只保存加密 Token；不保存原始密碼。
- 活動系統使用自己的 SSO 入口與返回目標處理，不再直接停在 `/Act/ApplyMe` 登入頁。
- 校方公開 JS 已確認 AppList DTO／預設 GET 契約，但 AppList 要求有效帳號（未登入回 401），尚不能確認活動 GUID 設定存在。SSO 不可用時退回已確認的活動登入頁，保留原始「我的報名」目標且持續監測登入完成；此分支仍可能要求再次輸入活動登入資料。
- 校方 Angular 登入頁的實際欄位、submit／登入按鈕與 Enter 行為已比對公開 JS，credentials 僅於使用者送出時暫用於 Moodle，不修改 Turnstile。
- 校方服務的實際驗證碼或伺服器要求仍需使用者完成，不宣稱略過校方驗證。

### 0.2.3 校務畫面修正

- 共用校務 WebView 的版面與導覽修正，載入、等待資料與逾時均有可見狀態。
- 課表與畢業門檻擷取支援同來源子框架，課表查詢等待按鈕就緒再單次執行。
- 校務頁面使用與 iOS 對應的 Referer；實際學校連線仍須以使用者帳號驗證。
- Android 16／WebView 133 的合成 HTML 擷取整合測試通過，涵蓋課表／畢業門檻正式腳本。另有平台 Host 尺寸、60 秒逾時與框架導覽 fixtures。

### 0.2.1 登入與通行碼調整

- 登入時只在學校頁面輸入一次帳號與密碼，App 向校方身分 API 確認帳號。
- 快捷入口取消額外的登入提示／解鎖畫面；先恢復 Session，必要時直接呈現校方登入並自動留在目的功能。
- 圖書館 QR Code 隨圖碼區域等比例放大；借書條碼使用橫向比例。
- 公測後續規劃自訂 PIN／生物識別，本版不啟用 App 鎖。
