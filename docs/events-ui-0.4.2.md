# 活動報名 UI／UX 0.4.2

沿用既有 Flutter design system、校方活動模型、登入與報名服務。

本輪重點：單一 Header、共用分段控制、可搜尋的精簡活動卡、分頁快照保留、詳情資訊分組，以及保留使用者主動送出的校方報名流程。

已完成程式碼整合；完整測試與APK建置結果於發布時記錄。

發布結果：`dart format .`完成、全專案分析無問題、180項測試通過、Android debug APK建置與簽署通過。Android16模擬器覆蓋安裝與冷啟動成功，下載HTTP200。

## 已實作

- `events_screen.dart` 單一外層Header、共用分段／搜尋、每頁籤快照及搜尋保留、同步防重入。
- 新增 `event_widgets.dart`：compact EventCard、具文字與圖示的EventStatusPill、EventFactGroup。
- 同步透過獨立校方頁進行，取消或失敗後回列表保留原資料與提示，不把取消當空清單。
- 詳情Hero與活動／內容／報名／聯絡分組，未知明確顯示；底部action安全區且最小48px。
- 查看詳情不重抓；使用者在校方變更後確認更新，才刷新可見頁籤。
- 新增 `events_design_test.dart`，涵蓋320px／2x字體深淺色、搜尋、切頁不重抓、詳情返回與更新結果。

## 驗收條件

- 可報名活動與我的報名切換保留各自搜尋／已取得資料。
- 活動名稱、狀態、時間、地點可辨識，不顯示原始JSON或空白資訊行。
- 查看詳情返回不重抓；使用者進入報名／管理表單返回才更新相關資料。
- 校方不提供狀態時顯示未知，不把未知當作可報名或已報名成功。
- 320px與2x文字深淺色下不裁切，搜尋鍵盤不遮住列表，底部動作遵守SafeArea。
- 不改寫或自動提交校方報名表單。

## 既有服務驗證

- 8項事件入口／獨立服務登入回歸通過，包括Session過期與帳號隔離。
- UI改動不變更活動form action或防偽欄位。

## 資料限制

活動時間、名額與資格為校方文字，無可靠結構欄位時保留可讀原文；不自行推算剩餘名額或保證可報名。
詳細報名表單由校方提供，App可統一外層導覽，不能假裝已將第三方表單轉成原生完成流程。
